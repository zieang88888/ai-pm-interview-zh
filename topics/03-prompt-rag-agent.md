# 03 Prompt / RAG / Agent

> AI 应用的三件套：怎么让模型听懂你、怎么喂它知识、怎么让它干活。

### Q1 【基础】什么是 Prompt Engineering？为什么 PM 要懂？

- **答题框架**：
  1. Prompt 是你给模型的指令；Prompt Engineering 是设计指令让输出更准、更稳。
  2. 常见技巧：角色设定、明确任务、给示例（Few-shot）、约束输出格式、分步指令（CoT）。
  3. PM 要懂的原因：Prompt 直接决定用户体验与功能效果，是"产品逻辑"的一部分。
  4. 产品化：把 Prompt 变成模板/配置，非技术人员也能调整。
- **追问点**：Prompt 和代码哪个更重要？边界在哪？

### Q2 【基础】什么是 Few-shot / Zero-shot？

- **答题框架**：
  1. Zero-shot：不给示例直接问，考验模型通用能力。
  2. Few-shot：给 2-5 个输入输出示例再问，显著提升格式与风格稳定性。
  3. 使用逻辑：任务越特殊、格式要求越强，越需要 Few-shot。
  4. 成本：示例会占上下文 token，要控制数量。
- **追问点**：什么时候 Few-shot 也没用？

### Q3 【基础】什么是 RAG（检索增强生成）？

- **答题框架**：
  1. 定义：先检索相关知识，再让模型基于检索结果生成答案。
  2. 解决两大问题：知识时效性（模型知识有截止日期）+ 幻觉（有原文可依）。
  3. 流程：文档切块 → 向量化 → 检索（语义相似）→ 拼进 Prompt → 生成。
  4. 适用：企业知识库问答、客服、文档理解。
- **追问点**：RAG 的检索质量怎么衡量？答得差是生成问题还是检索问题？

### Q4 【进阶】RAG 和微调有什么区别？怎么选？

- **答题框架**：
  1. RAG：改"输入"——动态检索知识喂给模型；不改模型本身。快、可更新、成本低。
  2. 微调：改"模型"——用领域数据训练，改变行为风格与知识内化。慢、贵、需维护。
  3. 选型：知识类（文档/FAQ）→ RAG；风格/格式/领域行为类（客服话术、垂直术语）→ 微调。
  4. 常见组合：RAG 为主 + 微调优化输出风格。
- **追问点**：RAG 的落地难点通常在哪？（召回率、切块、权限）

### Q5 【进阶】RAG 的完整评估指标有哪些？

- **答题框架**：
  1. 检索侧：召回率、精确率、检索相关性（命中正确文档的比例）。
  2. 生成侧：答案准确率、忠实度（是否忠于检索内容）、完整率、格式合规率。
  3. 体验侧：首 token 延迟、端到端延迟、失败率。
  4. 方法：人工评测集 + 自动化评测（LLM-as-judge）+ 线上指标（满意度、纠错率）。
- **追问点**：怎么判断"答得差"是检索没召回到还是模型没用对？

### Q6 【基础】什么是 Agent？Agent 的典型架构？

- **答题框架**：
  1. Agent = LLM + 工具 + 记忆 + 规划，能自主完成多步任务。
  2. 典型架构：感知（输入/环境）→ 规划（拆解任务）→ 行动（调用工具）→ 反思（看结果修正）。
  3. 关键组件：工具集（API/函数）、记忆（短期对话+长期向量库）、任务编排（ReAct/Plan-and-Execute）。
  4. PM 视角：Agent 产品核心是"任务边界 + 失败兜底 + 用户信任"。
- **追问点**：Agent 失败时怎么设计用户体验？

### Q7 【进阶】Agent 落地的最大瓶颈是什么？

- **答题框架**：
  1. 可靠性：多步任务任一步出错会连锁失败，准确率难到 99%。
  2. 成本：多轮工具调用 token 消耗大，性价比需要算清楚。
  3. 安全：工具权限放大，Prompt 注入风险，越权操作。
  4. 体验：黑盒执行让用户不信任，需要过程透明与人工接管点。
  5. 建议：从"低风险、高价值、流程标准化"的场景切入（如报表生成、客服工单）。
- **追问点**：你会选什么场景第一个上 Agent？为什么？

### Q8 【进阶】什么是 Function Calling（工具调用）？产品怎么用？

- **答题框架**：
  1. 定义：模型识别用户意图后，输出结构化调用（函数名+参数），由系统执行并回传结果。
  2. 价值：模型从"只说话"变成"能做事"——查天气、下单、查库存。
  3. 产品用法：定义好工具 Schema → 模型选择调用 → 校验参数 → 执行 → 结果回填。
  4. 风险：参数幻觉（编参数）、越权调用——要加参数校验与权限控制。
- **追问点**：工具调用参数填错了怎么办？

### Q9 【进阶】如何设计一个高质量的系统 Prompt？

- **答题框架**：
  1. 角色与目标：你是谁、帮用户达成什么。
  2. 能力与边界：能做什么、不能做什么、什么情况转人工。
  3. 流程与格式：分几步、输出什么格式（JSON/表格/步骤）。
  4. 安全与兜底：敏感话题怎么处理、识别不了意图怎么办。
  5. 迭代：用真实语料测试，看失败案例改 Prompt，形成版本管理。
- **追问点**：Prompt 上线后怎么持续优化？

### Q10 【实战】你的产品里，Prompt、RAG、Agent 各负责什么？

- **答题框架**：
  1. 拿自己/假设的产品举例，分层说明：Prompt 定风格与流程，RAG 供知识，Agent 编排动作。
  2. 举例：客服机器人——Prompt 管话术与情绪，RAG 查知识库，Agent 触发退换货/工单流程。
  3. 强调"组合拳"：单一技术解决不了完整问题。
  4. 补一句成本与风险意识：每层都有自己的失败模式与兜底。
- **追问点**：如果预算只够做一个，先做哪个？为什么？
