# 08 团队协作与项目管理

> AI 产品是团队活：怎么和算法、工程、设计、业务协作，怎么把项目推进。

### Q1 【基础】AI 产品团队一般有哪些角色？PM 怎么分工？

- **答题框架**：
  1. 角色：PM（定义价值/需求）、算法（模型/效果）、工程（系统/集成）、数据（采集/标注/分析）、设计（体验）、业务/运营（落地与反馈）。
  2. PM 职责：翻译——把业务需求翻译成技术需求，把技术能力翻译成产品价值。
  3. 协作关键：目标对齐（同一个指标）、节奏对齐（迭代周期）、信息透明（状态同步）。
- **追问点**：你和算法同学最容易在什么地方产生分歧？

### Q2 【基础】AI 项目怎么排期？有什么特殊性？

- **答题框架**：
  1. 传统排期假设"需求确定、工时可估"，AI 排期天然有不确定性。
  2. 特殊性：效果不确定（要评测迭代）、模型供应商不稳定、数据质量不可控。
  3. 对策：分阶段里程碑（MVP → 优化 → 上线），每阶段带验收标准。
  4. 预留缓冲：效果调优至少占 30-50% 周期。
- **追问点**：怎么给老板解释"效果还没达标，需要再延期"？

### Q3 【基础】怎么和算法/技术同学高效沟通需求？

- **答题框架**：
  1. 用"行为描述"代替"技术指令"：说"用户问 XX 时应该这样答"，别说"你要做 RAG"。
  2. 给数据与案例：真实请求样本、期望输出、失败案例。
  3. 给验收标准：评测集、指标、优先级。
  4. 尊重专业判断：效果边界由算法评估，PM 管价值与取舍。
- **追问点**：技术说"这个效果做不了"，你怎么判断是真做不了还是不想做？

### Q4 【进阶】AI 项目的迭代节奏怎么定？

- **答题框架**：
  1. 双轨制：产品功能迭代（周/双周）+ 模型效果迭代（评测/灰度，按效果数据驱动）。
  2. 模型灰度：小流量 → 扩大 → 全量，每步看指标。
  3. 数据回流：每轮迭代收集反馈，下轮改进。
  4. 上线节奏：效果稳定的模型版本 + 功能版本绑定发布。
- **追问点**：模型更新和功能更新撞车了，怎么安排？

### Q5 【进阶】模型效果一直不达标，怎么推动项目前进？

- **答题框架**：
  1. 先降预期：评估指标拆解——是检索问题、Prompt 问题还是模型能力问题。
  2. 换路径：RAG 优化、Few-shot、模型换型、加规则兜底。
  3. 降范围：砍掉难场景，先上线能达标的场景。
  4. 明决策：给出"继续投入 vs 止损"的判断依据，别无限优化。
- **追问点**：什么情况下应该砍掉一个 AI 功能？

### Q6 【进阶】怎么管理 AI 项目中的外部依赖（模型供应商）？

- **答题框架**：
  1. 供应商风险：API 不稳定、涨价、下架、数据合规。
  2. 对策：抽象模型层（可切换）、监控可用性、备份方案（备选模型/降级路径）。
  3. 合同管理：SLA、价格条款、数据条款。
  4. 技术评估：定期对比主流模型，保持选型主动权。
- **追问点**：主模型供应商涨价 50%，你的应对方案？

### Q7 【进阶】AI 产品上线前的"验收清单"有哪些？

- **答题框架**：
  1. 效果验收：评测集达标率、核心指标达标。
  2. 安全验收：内容审核、注入防护、越权测试。
  3. 合规验收：隐私政策、数据授权、备案要求。
  4. 稳定性验收：并发、延迟、限流、故障恢复。
  5. 体验验收：失败路径、纠错路径、兜底提示完整。
- **追问点**：哪一项最容易漏？漏了会怎样？

### Q8 【进阶】AI 产品的文档（PRD）怎么写？有什么特别注意？

- **答题框架**：
  1. 常规内容：背景、目标用户、功能流程、交互、指标。
  2. AI 特有：能力边界（能做什么/不能做什么）、失败路径与兜底、Prompt 策略、评测方案、数据需求、成本预算。
  3. 验收标准要"可测"：给评测集规模与达标线。
  4. 版本规划：模型/数据依赖写清楚。
- **追问点**：PRD 里的"AI 效果"部分怎么写才不被技术怼？

### Q9 【进阶】和业务方（运营/销售/客户）的需求冲突怎么处理？

- **答题框架**：
  1. 业务方要"万能 AI"，技术做不到 → 用能力边界 + 优先级排序回应。
  2. 建立需求池：所有需求进池，按价值/成本/依赖排序。
  3. 透明度：定期同步进度与效果，让业务方参与验收。
  4. 原则：对业务说"能做什么、什么时候能、代价是什么"，不说空话。
- **追问点**：客户坚持要一个技术上不现实的功能，怎么办？

### Q10 【实战】你作为 AI PM，怎么向团队传达"这轮效果不好"？

- **答题框架**：
  1. 数据先行：给指标、给失败案例，说清楚差在哪。
  2. 归因客观：是数据、模型、需求还是预期问题，不甩锅。
  3. 给下一步：明确调整方向与时间点。
  4. 稳定军心：区分"暂时不达标"与"方向错误"，管理预期。
- **追问点**：老板当众质疑项目价值，你怎么回应？
