# 02 大模型原理与能力边界

> AI PM 不需要会写模型，但必须讲清楚"模型能做什么、为什么这么做、边界在哪"。

### Q1 【基础】用一句话向非技术人员解释大模型是怎么工作的？

- **答题框架**：
  1. 大模型通过海量文本学习"词与词的搭配规律"，本质是超强的"根据上文预测下文"引擎。
  2. 预训练阶段读遍互联网文本，学会语言与知识；微调/对齐阶段学会"像人一样回答问题"。
  3. 你输入一句话，模型按概率生成最合适的下一个词，循环生成完整回答。
  4. 它"会说话"但"不会查证"——这就是幻觉的根源。
- **追问点**：那它到底是"理解"还是"模仿"？

### Q2 【基础】什么是 Transformer？为什么它成为大模型的基础架构？

- **答题框架**：
  1. Transformer 是 2017 年提出的深度学习架构，核心是注意力机制（Attention）。
  2. 注意力机制让模型能关注输入序列中任意位置的信息，解决长距离依赖问题。
  3. 相比 RNN：可并行计算（训练快）、长文本效果好、规模可扩展。
  4. 大模型 = 更大规模的 Transformer（层数/头数/参数），这就是"大力出奇迹"的架构基础。
- **追问点**：注意力机制和人类阅读的注意力有什么相似？

### Q3 【基础】什么是 Token？为什么计费和上下文都按它算？

- **答题框架**：
  1. Token 是模型处理文本的基本单位：中文约 1 字 ≈ 1-2 token，英文 1 词 ≈ 1-2 token。
  2. 输入和输出都按 token 计费；上下文窗口 = 模型一次能处理的 token 上限。
  3. PM 影响：长文档/长对话消耗大；产品设计要考虑 token 成本与上下文管理。
  4. 优化手段：摘要压缩、按需检索、截断、分块。
- **追问点**：一个 10 万 token 的上下文窗口，能放多少汉字？

### Q4 【基础】什么是上下文窗口？超了会怎样？

- **答题框架**：
  1. 上下文窗口是模型一次对话能"记住"的 token 总量（输入+输出）。
  2. 超过上限：早期直接报错；现在多支持自动截断或压缩，但会"失忆"。
  3. 影响：长文档问答、长代码、多轮对话都受窗口限制。
  4. PM 策略：设计"上下文预算"——核心信息常驻，次要信息按需检索。
- **追问点**：RAG 是不是解决了上下文不够的问题？还有哪些局限？

### Q5 【进阶】什么是预训练、微调、对齐？三者的区别？

- **答题框架**：
  1. 预训练：海量无标注文本学习语言规律，得到"基座模型"（会续写，不会好好答）。
  2. 微调：用带标注的特定任务数据继续训练，让模型适配垂直领域/任务（如客服语料微调）。
  3. 对齐（RLHF 等）：让模型符合人类偏好——有用、安全、不胡说，变成"会好好回答"的助手。
  4. 比喻：预训练是"读万卷书"，微调是"考证书"，对齐是"学做人"。
- **追问点**：产品什么时候需要微调，什么时候 RAG 就够了？

### Q6 【进阶】什么是 RLHF？为什么它对大模型这么重要？

- **答题框架**：
  1. RLHF = 人类反馈强化学习：用人类标注的"好/坏回答"训练奖励模型，再强化学习优化策略。
  2. 解决"会写但不会好好答"：引导模型生成人类更喜欢的回答（有用、诚实、无害）。
  3. 三个模型：策略模型 + 奖励模型 + 人类反馈数据。
  4. 局限：成本高、可能过度迎合（谄媚）、奖励黑客。
- **追问点**：RLHF 之后的模型为什么有时会"过度道歉"？

### Q7 【进阶】模型的"推理能力"指什么？为什么最近推理模型这么火？

- **答题框架**：
  1. 推理能力：解决需要多步逻辑、数学、规划问题的能力，而非简单回忆。
  2. 推理模型（如 o1/DeepSeek-R1）通过"思考链"（CoT）+ 强化学习，让模型先想后答。
  3. 原理：训练时鼓励模型生成逐步推理过程，并自我纠错。
  4. 代价：推理时间更长、token 消耗更大；适合复杂任务，简单问答用不上。
- **追问点**：你的产品里哪些场景值得用推理模型？成本怎么控？

### Q8 【进阶】什么是多模态模型？和纯文本模型比强在哪？

- **答题框架**：
  1. 多模态：同时处理文本、图像、音频、视频，能"看图说话"。
  2. 优势：理解视觉信息（截图、设计稿、图表）、跨模态生成（图生文、文生图）。
  3. 应用：文档 OCR + 理解、截图转代码、图片审核、视频理解。
  4. 局限：多模态推理深度不如文本，成本更高，幻觉在视觉上同样存在。
- **追问点**：给你一个"拍照识别植物"的需求，你怎么设计？

### Q9 【进阶】大模型的能力边界有哪些？哪些事它做不好？

- **答题框架**：
  1. 事实准确性：会幻觉，无实时知识（除非检索）。
  2. 精确计算与确定性任务：数学计算、精确数据库操作不可靠。
  3. 长程规划：多步骤长任务容易跑偏，需要外部编排（Agent 框架）。
  4. 私密与安全：数据合规、Prompt 注入、内容安全。
  5. PM 心态：把模型当"高能力高方差实习生"，用工程手段兜底。
- **追问点**：你的产品怎么设计兜底方案？

### Q10 【实战】让你给非技术老板讲"我们产品的 AI 能力原理"，你怎么讲？

- **答题框架**：
  1. 不用术语，用比喻：模型像一个读过海量书、能快速组合知识的助手。
  2. 讲能力不讲架构：能做 XX、不能做 XX、边界在哪。
  3. 讲商业价值：降本、增效、体验提升的具体数字。
  4. 讲风险与投入：成本、准确率、合规，给出管理预期。
- **追问点**：如果老板问"为什么有时答错"，你怎么回答？
