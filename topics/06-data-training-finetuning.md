# 06 数据、训练与微调

> 与技术同学对话的底气：数据从哪来、模型怎么训、PM 在中间管什么。

### Q1 【基础】AI 产品的数据从哪来？

- **答题框架**：
  1. 自有数据：用户行为、业务系统、历史问答——最有价值。
  2. 公开数据：开源数据集、爬取公开内容（注意合规）。
  3. 合成数据：用大模型生成训练数据（降本增效，需质检）。
  4. 众包/人工标注：外包标注团队、众包平台。
  5. PM 职责：定义"需要什么数据、怎么采集、怎么保证质量"。
- **追问点**：数据量不够怎么办？先列三招。

### Q2 【基础】什么是数据标注？PM 怎么管理标注质量？

- **答题框架**：
  1. 标注：给数据打标签（分类、打分、写标准答案），是监督训练与评测的基础。
  2. 质量管理：标注规范文档 + 示例 + 试标培训。
  3. 过程控制：双人标注 + 仲裁、抽检、一致性（Kappa）计算。
  4. 迭代：标注问题回流修订规范。
- **追问点**：标注成本和模型效果怎么平衡？

### Q3 【基础】什么是训练集、验证集、测试集？为什么要分开？

- **答题框架**：
  1. 训练集：教模型学规律。
  2. 验证集：训练中调参、选版本。
  3. 测试集：最终验收，模型没见过的数据。
  4. 分开的原因：防止过拟合——模型"背下"训练数据，测试集才能反映真实能力。
- **追问点**：测试集被污染（模型见过）会怎样？

### Q4 【进阶】你的产品需要微调吗？判断标准是什么？

- **答题框架**：
  1. 先问：RAG/Prompt 能否解决？大多数需求先用它们。
  2. 需要微调的信号：输出风格/格式强要求、垂直术语密集、RAG 后仍不达预期。
  3. 成本评估：数据准备、训练周期、模型维护、效果回退风险。
  4. 结论：宁可先上 RAG + 强 Prompt，验证需求真实后再微调。
- **追问点**：微调后的模型效果变差（灾难性遗忘）怎么办？

### Q5 【进阶】什么是 LoRA？为什么微调常用它？

- **答题框架**：
  1. LoRA = 低秩适配：冻结原模型，只训练一小部分低秩参数。
  2. 优点：显存/算力要求低、训练快、可以多任务多副本切换。
  3. 对比全量微调：效果略逊但性价比极高，工程上更稳。
  4. 适用：垂直风格适配、领域指令微调。
- **追问点**：LoRA 副本多了怎么管理？

### Q6 【进阶】什么是数据清洗？常见问题有哪些？

- **答题框架**：
  1. 清洗目的：去噪、去重、去毒、去敏感信息，保证训练数据质量。
  2. 常见问题：重复数据（过拟合）、错误标签、低质量文本、隐私信息（PII）。
  3. 方法：规则过滤 + 模型去重 + 人工抽检。
  4. PM 视角：数据质量直接决定效果上限——"垃圾进，垃圾出"。
- **追问点**：敏感信息怎么脱敏？

### Q7 【进阶】提示词注入（Prompt Injection）是什么？怎么防？

- **答题框架**：
  1. 定义：用户输入中夹带恶意指令，诱导模型越权/泄密/执行危险操作。
  2. 典型场景：客服机器人的 Prompt 被用户"劫持"、网页内容注入。
  3. 防御：输入过滤、指令优先级隔离、输出校验、权限最小化、模型对齐。
  4. PM 职责：把注入当安全需求做测试与监控，敏感操作加人工确认。
- **追问点**：RAG 的知识库里被投毒怎么发现？

### Q8 【进阶】AI 产品的数据合规要注意什么？

- **答题框架**：
  1. 个人信息保护法（PIPL）：采集授权、目的限制、最小化。
  2. 数据出境：跨境传输需评估与申报。
  3. 内容合规：生成内容审查（涉黄涉政、暴力、歧视）。
  4. 版权：训练数据与生成内容的版权风险。
  5. 落地：隐私政策、用户授权流程、内容审核机制、日志留痕。
- **追问点**：用户上传的数据用于模型训练，需要怎么处理？

### Q9 【进阶】怎么向技术同学提出"好"的模型需求？

- **答题框架**：
  1. 说清场景与目标：用户任务、期望行为、边界。
  2. 给数据与案例：真实用户请求样本 + 期望输出示例。
  3. 给验收标准：评测集、指标、最低可接受水平。
  4. 给优先级：核心场景先做，长尾后置。
  5. 避免"技术黑话"，用"行为描述"沟通。
- **追问点**：技术说"做不到 99% 准确率"，你怎么回应？

### Q10 【实战】模型效果上线后下滑了，你怎么排查？

- **答题框架**：
  1. 先看时间线：是不是模型版本升级/供应商变更/数据分布变化。
  2. 拆输入侧：用户请求分布是否变了（新场景/新话术）。
  3. 拆系统侧：RAG 检索、前置规则、Prompt 是否被动过。
  4. 拆评估侧：指标口径是否变化、评测集是否更新。
  5. 结论：先回滚/冻结变量，逐层定位，别一次改一堆。
- **追问点**：用户请求分布变了导致效果下滑，产品上怎么应对？
